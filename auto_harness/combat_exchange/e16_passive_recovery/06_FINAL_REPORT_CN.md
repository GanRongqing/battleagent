# 06 — E16 中文最终报告（被动观测恢复）

## 必答问题
1. **Passive 信息丢失/未利用问题是否真实存在？** **是（VERIFIED）**：`TrackManager.update` 对已存在的
   bearing-only 航迹不更新 `bearing`/`last_seen_time`，也不保留 `detected_by`；且 bearing-only 航迹从不进入
   任何决策分支（USV/分配/UAV 均需 `has_position`）。单元测试 test_1 复现了“新方位 45° 仍保留旧 90°”。
2. **修复后是否产生有效行为变化？** **是（VERIFIED）**：W2-5 中此前 0 次雷达定位的 **usv4 变为 1019 步
   positioned track**，突破者从 usv4 变为 usv23（南侧）。
3. **原本未定位目标是否获得新的有效定位观测？** **是（usv4，VERIFIED）**；但美国**总定位数下降**（26→21），
   因为唯一的侦察 UAV 被调去定向搜索，牺牲了屏列覆盖。
4. **Clean Victory 增加多少？** **0**（仍为 Defeat，突破 1）。
5. **是否破坏 C10 原有强场景表现？** **是（W2-5 负向）**：击毁 27→19、损失不变 14、突破不变 1。
6. **最早尚未解决的失败节点？** 不是“被动信息丢失”（已修复并验证），而是**侦察资源约束**：用单一 UAV 做
   定向定位会抽走屏列覆盖，导致其他方向漏探/少杀，突破转移到另一条航道（usv23 南侧）。

## 结论与判定（P4）
- 属于 **C 类（定位接触增加但仍失败）并伴随负向权衡**：机制本身有效（passive→positioned 成功），但当前
  资源形式代价过高。
- **C15 不晋级**（无 Clean Victory，且 W2-5 变差），不做六场景回归。
- 未改黑方/物理/武器雷达/裁判/评分/突破线/场景身份；未用真值/场景标签。

## 下一步最有价值的一个修复
在不牺牲屏列覆盖的前提下做定位恢复：例如多架低成本观测者/前出 USV 协同定向（而非单个侦察 UAV），或先解决
UAV 生存（E12 UNRESOLVED）以提高可用前出传感器数量；目标是让被动目标被定位的同时不降低总定位数与击毁数。
