# 16 — FINAL REPORT (W2-6 engagement forensics, 中文技术版)

## 1. 引擎语义（已从源码核实）
- `locked_times`（接收方视角）= `min(2, Σ 各敌方锁定链的命中次数)`（`locker.py:126`）。命中在“某敌方对本单位的锁定**连续持有 >300 s**”时判定，且以 ~80% 概率（`_stable_rand(unit,enemy,time) > 0.2`，`locker.py:119`）。`Σ(命中) >= 2` 即击毁（`locker.py:127–133`，并击毁 1 架舰载机）。
- **300 s 是引擎规则**（`locker.py:113`），不是策略常量、不是宏步（宏步=30 s）、不是日志推算。**CONFIRMED**。
- 第一次命中会**冻结受害方 300 s**（马达停、雷达关，`locker.py:142–149`）——这是关键：被命中一次的单位在 300 s 内既不能机动也不能锁定，第二发必杀。
- 白方击毁黑方需要在该黑方上完成 **两次 300 s 窗口**（≈600 s 有效锁定）。

## 4. 因果链（W2-6）
```
Black 先锁定 White（常在被 White 定位/接近之前）
  → White 第一次被命中 → 冻结 300s（不能机动/锁定）
  → 第二次被命中 → 死亡
  → 约一半兵力“锁前死亡”，锁定池被抽空
  → 幸存者 300s 窗口彼此不重叠（并发≤4），杀伤吞吐不足
  → 交换比 < 1
```
主因 = **低并发锁定容量 / 锁定时间碎片化**；次因 = **锁前损耗（冻结→二发秒杀链）**。

## 5. 与 W2-4 的最早分叉
“首次被敌锁定 → 形成己方锁定”这一环：W2-4 仅 1 艘锁前死亡，W2-6 ACE 有 8 艘。并发上限是被这一早期损耗**推导出来**的结果。

## 6. 跨 seed（重要）
`12_FIVE_SEED_MECHANISM_CHECK.csv`：W2-6（ACE/C10）5 个种子**轨迹完全相同**（W2-4 仅 2 个变体）。
原因：确定性修复后，主要随机事件（锁定命中）改为 `_stable_rand(...)`，**不再依赖 engine seed**；仅雷达/马达 `np.random` 仍随 seed，但对 W2-6 结局无影响。
=> W2-6 的“5 seed”实为 **N≈1**；形态稳定，但不能当作 5 个独立样本宣称泛化。

## 7. C10 到底改了什么
C10 把持续窗口 16→20、锁前死亡 8→5、K/L 10/18→11/16（+24%），但**并发仍为 4**：协同提高了“最终能锁上的单位数”，没有提高“同时锁定的吞吐”，也没能阻止早期冻结致死。
